# 2026-10-27 — Сохранение лута на сцене и душ (урок 10 Loot)

## Проблема

Неподобранный лут после перезапуска пропадал; души (`LootData.Collected`) сохранялись только на `SaveTrigger`.

## Что сделали

- По курсу (итог урока 10, задание «10 WireUpTestAndTask»): `Data/DictionaryData_Base` (словарь для `JsonUtility` через `ISerializationCallbackReceiver`), `LootPieceData`, `LootPieceDataDictionary`, `LootData.LootPiecesOnScene`; `UniqueId.GenerateId()` (его же вызывает `UniqueIdEditor`); `LootPiece : ISaveProgress` — пишет себя в словарь, восстанавливается по id, при подборе удаляет запись; `EnemyLootSpawner` → `GenerateId()`; `LoadSceneState.InitLootPieces()` до игрока.
- Отступление (решение пользователя): `LootPiece` при подборе вызывает `SaveProgress()` (сервис — из `ServiceLocator`, как в `SaveTrigger`). Минус: сохраняется весь прогресс, в том числе позиция игрока.
- Редактор: `UniqueId` на корне `Loot.prefab` (пользователь, проверено по файлу).

## Неочевидное

- Без `UniqueId` на префабе — NRE при выпадении лута.
- Старое сохранение без `LootPiecesOnScene` может упасть в `DictionaryData_Base.OnAfterDeserialize` — перед проверкой `Tools → Clear Prefs`.

## Проверка

`0 error CS`; пользователь в Play Mode: неподобранный лут на месте после перезапуска, подобранный не появляется, души сохраняются.

Бриф: `Ai.Tasks/2026-10-27-loot-save.md` (локально).
