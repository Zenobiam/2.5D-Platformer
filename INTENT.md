# INTENT — зачем этот проект

Источник истины по целям. `Ai.Context/project-context.md` § 1 и `.cursor/rules/project-goals.mdc` ссылаются сюда; при расхождении побеждает этот файл. Меняется только решением пользователя (запись в `Ai.Decisions/`).

## Зачем

Учебный **эталон** по курсу k-syndicate «Архитектура мобильных игр на Unity» (2021, Unity 2019.3), перенесённый на Unity 6, **плюс документация**, по которой следующий Unity-проект (в том числе с AI-агентами) стартует быстрее. Игра — 2.5D platformer: движение по X, поворот модели, прыжки, враги, сохранение прогресса, сцены через game state machine. Платформа — мобильная по курсу; **пока основная — ПК** (`Ai.Decisions/2026-10-30-pc-first.md`): проверяем под мышь и клавиатуру, мобильные части курса сохраняем.

## Цели

1. **Архитектура курса, урок за уроком:** bootstrap, game state machine, сервисы, ServiceLocator, фабрики, провайдер ассетов, прогресс — в порядке уроков.
2. **Современный Unity:** API Unity 6 вместо устаревших; каждое отступление от кода курса записано (`Ai.Architecture/course-deviations.md`).
3. **Код как образец для копирования:** читаемый, повторяемый, переносится в другой проект с минимальной адаптацией.
4. **Мобильная игра всерьёз:** экранные кнопки для каждого действия, без аллокаций в кадре. Пока основная платформа — ПК (решение 2026-10-30): то, что на ПК неудобно, правим под ПК с записью в `course-deviations.md`, мобильные части не выбрасываем.
5. **Документация совпадает с кодом:** канон `Ai.*`, правила `<Knowledge>` — проверяемые и актуальные.

## Не-цели

- Не выпускаемая игра: контент, баланс и полировка ассетов — только сколько нужно для урока (заглушки анимаций допустимы, если отмечены).
- Не «улучшенный курс»: свои паттерны, интерфейсы, DI-контейнеры (Zenject, VContainer) и рефакторинги сверх курса — только по просьбе пользователя. Ревизия архитектуры — после конца курса.
- Не витрина инструментов агентов: процессы и автоматизация — ровно настолько, насколько они помогают проходить уроки.

## Как выбирать при сомнении

По порядку, первое подходящее решает:

1. Явное решение пользователя (чат, `Ai.Decisions/`).
2. Как сделано в коде курса (итог урока — см. `Ai.Architecture/course-map.md`).
3. Если API курса устарел или плохо работает на мобилке — современный аналог Unity 6 + строка в `course-deviations.md`.
4. Ясность и переносимость важнее краткости и хитрости.
5. Не уверен — спросить пользователя, а не выбирать молча.

## Готовность

Урок считается пройденным, когда: код урока перенесён, отступления записаны, проект компилируется без ошибок, пользователь проверил в Play Mode, бриф в `Ai.Tasks/` закрыт итогом, канон обновлён.
