# 2026-10-25 — Статические данные: Unity ScriptableObject, не JSON

Статус: accepted (как в курсе, урок 09 Static data)
Контекст: параметры врагов (HP, урон, дистанции, скорость, префаб) уходят из Inspector префаба в отдельные данные, которые загружает `StaticDataService`. Нужно выбрать формат хранения. Курс сравнивает два варианта.

Решение: **ScriptableObject** (`MonsterStaticData`, ассеты в `Resources`), загрузка `Resources.LoadAll` один раз в `BootstrapState`.

Почему (слайды курса; общее правило для проектов — `<Knowledge>\conventions\static-data.md`):

| | ScriptableObject | JSON |
|---|---|---|
| Редактирование | встроенный удобный тулинг: Inspector, `[Range]`, ссылки на ассеты (поле `Prefab`) перетаскиванием | нужен свой тулинг (редактор, валидация); ссылку на префаб — только строкой-путём |
| Скорость | бинарная сериализация в билде — быстро | строковый формат: сериализация и десериализация дороже по CPU |
| Память | намного меньше | объёмный (строки) |
| Читаемость | в билде бинарный — человеку не прочитать | читается глазами |
| Универсальность | читает только Unity | стандарт, читают любые сериализаторы и серверы |

Для учебного проекта на мобилке решают тулинг, скорость и память: данные правит разработчик в Inspector, ссылку на префаб удобно держать прямо в ассете.

Нюанс для проекта: в репозитории ассеты хранятся как текстовый YAML (Asset Serialization: Force Text), поэтому диффы в git читаемые; бинарный формат — это то, что попадает в билд.

Отвергнуто:
- **JSON** — сейчас не нужен: нет сервера и обновлений данных без билда, а свой тулинг и строковые ссылки на префабы — лишняя работа.

Где лежат ассеты (решение пользователя 2026-10-25): общая папка `Resources/StaticData/Enemies` + `LoadAll`, как в итоговом коде курса. Вариант «папка на монстра» (`Enemies/{Id}/staticData`) записан в `<Knowledge>\conventions\static-data.md`. Принцип: людям на этапе разработки проще много мелких файлов, а для загрузки с сервера и обновлений лучше один файл — мелкие ассеты для правок, сборка в один файл для доставки, код читает через сервис.

Когда пересмотреть: если данные должны приходить с сервера и обновляться у игрока без нового билда (схема курса: тулинг → данные ← сервис → update → game client). Тогда варианты — JSON с сервера или ScriptableObject через удалённый контент Addressables (урок 15 курса).
